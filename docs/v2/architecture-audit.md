## 5. Listener, parser and cheap dedup deep audit

VERIFIED — Listener lifecycle and session access: Telethon connects to pre-existing sessions and registers NewMessage, MessageEdited and MessageDeleted callbacks (`src/estateflow/adapters/telethon_listener.py:44–55`, :86–97). Updates use an in-memory asyncio queue (:42, :102–107). Deletes emit one raw update per deleted message with local current time and no prior text/media (:130–146). The listener run loop then skips every update lacking text/media (`src/estateflow/services/telegram_listener.py:251–252`), which includes these delete callbacks: normal runtime deletes never reach handle_update/publication. Direct handler tests alone cannot establish runtime delete delivery. Transport event availability, Telegram reconnect catch-up completeness and private-group delete identity are NOT VERIFIED on live sessions; none were opened.

VERIFIED — Listener identity: raw keys are channel/message/event_type, with no edit revision (`src/estateflow/services/telegram_listener.py:467–482`). Redis mark_seen has no TTL (:157–168). Publish precedes mark_seen (:500–519), allowing duplicate publication if the process dies between them; separate seen checks are not a distributed claim. Repeated edits share the same key permanently while retained. No application-level persistent offset journal or session lease was found in these constructors. Telegram session handling must be an explicit transport ownership concern, including media retrieval.

VERIFIED — Albums: only created events with media_group_id are buffered (`src/estateflow/services/media_buffer.py:41–65`). Debounce groups reside in memory, are popped before downstream publish (:92–111), and ordinary publication exceptions restore the group in memory and re-raise (:112–125). The failed debounce task does not schedule another attempt (:127–132), leaving recovery to a later member or graceful flush. Graceful flush exists (:76–90); abrupt termination cannot execute it. Canonicalization sorts message IDs, combines text/media, uses an album key and retains original member IDs (:135–170). Late pieces can be discarded once the album key is seen; edits and deletes bypass album assembly. V2 needs durable member records, bounded settling, explicit late-update semantics and delete-to-album/candidate lineage.

VERIFIED — Source policy and refresh: source ORM stores both transport configuration and parser policy (`src/estateflow/models/listeners.py:51–134`; parser migration `alembic/versions/a1c4e7f9b2d6_add_source_parser_policy.py:29`). Listener embeds a deep-copied binding/provenance snapshot in raw events (`src/estateflow/services/telegram_listener.py:406–423`). Coordinator groups adapter/session, computes fingerprint, stops old supervisor and builds a new one (`src/estateflow/services/listener_refresh.py:196–253`, :414–430). Redis counter/pubsub signals refresh (:69–86); polling refreshes on version change only (:526–540). Active assignments/health are memory despite available SQL repositories (:124–132). SUSPECTED: concurrent poll/pubsub refreshes or missed DB-to-Redis signal can leave stale/repeated supervisor state; serialize refresh and test lost-signal reconciliation before extraction.

VERIFIED — Parser routing: precedence is event/payload metadata, source binding, registered recipe/fallback (`src/estateflow/services/source_parsing/router.py:104–139`, :180–225). Recipes include single listing, digest, album caption and mixed-feed include/exclude policies (:29–69). Bad config/plugin failures become routing errors (:129–168); mixed feed exclusions may drop and unmatched segments quarantine. Disabled mode is passthrough (:120–127), not source disablement. Shadow emits legacy passthrough, while active publishes rejected segments (`src/estateflow/services/ingestion_pipeline.py:52–69`).

VERIFIED — Buffering/quarantine: buffered_thread returns a buffer decision without a configured state store (`src/estateflow/services/source_parsing/parser.py:30–37`); ingestion explicitly converts it to passthrough with buffer_unavailable_fail_open (`src/estateflow/services/ingestion_pipeline.py:70–84`). Quarantine stores full raw payload plus cleaned rejected text and deterministic ID (:133–164), then the raw input is ACKed on normal return by the runner. There is no automatic consumer in split entrypoints. Retention, operator ACLs and safe replay must be specified, including partially emitted digests and duplicate quarantine writes after retries.

VERIFIED — Candidate identity: digest fanout isolates source_message_id while retaining original member IDs (`src/estateflow/services/source_parsing/contracts.py:208–239`). Candidate hash includes raw event, parser identity/version, index and cleaned text (:364–392); synthetic fanout ID uses raw message and index (:395–403). Changed parser versions/text can change candidate IDs and index mapping. V2 needs explicit supersedes/retract semantics rather than assuming candidate_id is permanent source identity.

VERIFIED — Cheap dedup: exact forward or normalized text matches skip AI (`src/estateflow/services/pre_ai_dedup.py:173–210`); near text, media and phone signals remain reviewable (:267–307). Store is an unbounded in-memory list (:127–147); default audit sink is disabled (:104). Signals are added after downstream publish (`src/estateflow/services/ingestion_pipeline.py:99–115`), so restart/replicas change behavior and replay is not atomically consumed. StableMediaReferencePHashProvider hashes the access hash/media ID, not image pixels (`src/estateflow/services/pre_ai_dedup.py:117–124`). Preserve this as a reference signal, not a perceptual similarity guarantee. No explicit delete/tombstone branch exists in the traced parser/pre-AI/AI methods; deletes must bypass cheap dedup and extraction in V2.

## 6. AI, media, catalog, search and delivery

VERIFIED — AI: split worker constructs OpenRouter client, media service and memory processing records (`services/worker_ai/main.py:31–53`). Media is prepared before prompt construction (`src/estateflow/services/ai_worker.py:117–140`). Normalization validates extracted content (:249), business gates reject low quality (:257–272), and manual-review results can be published (:330–334). LLM quality fallback validates schema, rental classification and required fields (`src/estateflow/services/ai_client.py:342–390`). OpenRouter transport sets request timeout and classifies 408/409/425/429/5xx as retryable (`src/estateflow/services/ai_client.py:144–176`); broker retries can repeat a full model fallback sequence. Schema validation is not semantic accuracy; production extraction precision, model cost and fallback latency are NOT VERIFIED. Only the split handler explicitly escalates selected retryable returned failures (`services/worker_ai/main.py:65–71`). Durable run records and reason-classified terminal events are required.

VERIFIED — Media: SmartMediaResolver can open a separate Telegram session using settings/Redis/auth service (`src/estateflow/services/media_storage.py:164–200`), so media is not independent of transport credentials. Download/processing errors are skipped (:402–414), upload failure cleans already stored objects (:455–463). Compression merely truncates bytes and appends a digest, and resized dimensions can be reported without resizing the content (:368–380). The method named phash_image hashes format/dimension bucket plus first bytes (:592–594). Decode validity, visual similarity and media completeness need real-format fixtures before independent deployment. Object keys use .jpg regardless of source format (:597–606). Keep AI/media together initially, establish actual image transformation and readiness semantics, then revisit separation based on latency/cost evidence.

VERIFIED — Post-AI: scoring considers candidate signals, exact anchors and thresholds (`src/estateflow/services/post_ai_dedup.py:548–614`); source/forward identity and complete structured fingerprints can outrank raw score. Canonical merge/review need to remain one catalog aggregate. Source conflict upsert is a no-op update, not edit application (`src/estateflow/repositories/post_ai_dedup.py:341–344`). Manual review approval methods mutate catalog (`src/estateflow/services/post_ai_dedup.py:993–1105`) without the split event_queue path. Existing-parent merge updates parent state but does not publish a changed parent event (:1425–1435). New parent can publish before merge (:1414–1423). An event-fed search projection would consequently miss catalog changes if built from the current persisted queue unchanged.

VERIFIED — Search: runtime uses SQLAlchemySearchRepository (`src/estateflow/application/runtime.py:181`), which directly queries active parent announcements and excludes one-time prices (`src/estateflow/repositories/sqlalchemy.py:394–405`). Broad exceptions become successful empty search results (:481–492), obscuring outage versus no match. Conversion omits media (:1479–1528), while alternative asyncpg search reads announcement_media (`src/estateflow/repositories/search.py:53`). Preserve price basis/monthly normalization/null-price/district/tag/pagination semantics and actual media behavior in parity fixtures; do not assume all repository implementations are equivalent.

VERIFIED — Notifications: matcher scans filters, checks active user/premium, commits jobs then publishes only when created (`src/estateflow/services/notifications.py:581–619`; `src/estateflow/repositories/sqlalchemy.py:1138`). The alternative asyncpg delivery repository uses FOR UPDATE SKIP LOCKED (`src/estateflow/repositories/notifications.py:191–199`), but the split runtime wires SQLAlchemy. Delivery reads listing/filter state directly (:1182–1195), claims pending via unlocked SELECT then commits sending (:1205–1220). It sends Telegram then commits sent/attempt (:1223–1260; `src/estateflow/services/notifications.py:449–494`). Retryable failures persist next_attempt_at and return normally (:455–488). Split worker only calls process_job (`services/worker_notification_delivery/main.py:43–51`), unlike legacy batch polling (`src/estateflow/services/queue_consumer.py:60–65`). Sending has no reclaim lease in the inspected methods. Default application limiter is disabled (`src/estateflow/services/notifications.py:367`).

VERIFIED — Other business paths: identity/referrals/saved-filter activation, source suggestions and premium grants, taxonomy remaps, content automation and analytics are real V1 behavior, absent or underspecified in the candidate service table. Content sends before saving its post (`src/estateflow/services/content_automation.py:298–315`), repeating the ambiguous external-side-effect window. ContentScheduleService publishes a separate scheduled-content contract (:398–425), with no dedicated split consumer found. Website scraper has no result repository by default and has no raw event publication in scrape_source (`src/estateflow/services/website_scraper.py:149–179`). Do not silently treat website ingestion as durable parity with Telegram.

## 9. Changes recommended to the proposed V2 specification

1. Approve a **domain ownership map before service count**. Keep canonical listing, parent/child merge, review and media attachment references in catalog. Keep users/referrals/premium awards in identity. Give filters/matching/jobs one notifications owner initially; split delivery behind immutable self-contained requests once recovery is proven. Evidence: T1/T2/T6 in the table map. APIs and bot are adapters, not implicit owners of all tables.
2. Add explicit control/source-management, taxonomy, content and analytics ownership. Admin audit should become owner-local audit with an event-fed central view; current shared admin_audit_events must not remain a write sink shared by every service. Evidence: `src/estateflow/repositories/sqlalchemy.py:675`, :810, :979; runtime :179–220.
3. Split transport source configuration from parser policy. Listener needs approved subscription/session state; parser owns recipe policy and history. Preserve the existing raw binding snapshot for deterministic historical replay and specify explicit reparse-under-new-policy commands. Evidence: raw snapshot `src/estateflow/services/telegram_listener.py:406–423`.
4. Keep AI/media co-deployed first; remove session access from general AI code only after an authorized media-fetch boundary and readiness contract exist. No media split solely by name: current media opens Telegram sessions (`src/estateflow/services/media_storage.py:164–200`). Catalog attachments can remain immutable copied references without a cross-schema FK.
5. Use a new exchange name for V2; add source revision, album/candidate lineage, canonical ID, tombstone and media-state contracts. Publish every catalog mutation, not just initial inserts; event-fed search cannot start from current persisted events alone. Evidence F04/F09/F10.
6. Define delivery as at-least-once processing with explicit ambiguous external send policy. Outbox/inbox cannot make Telegram side effects exactly once. Due scheduling, atomic leases and reconciliation must precede scale-out. Evidence F01–F03.
7. Retain shared PostgreSQL Variant A, with one migration owner per schema, restricted runtime grants, owner-local constraints and compatibility backfill. No cross-schema FK or shared write transaction should survive as a shortcut. Negative grants, default privilege/sequence tests and restore rehearsal are acceptance criteria, not assumed infrastructure facts.
